## Claude Cowork: agentic AI for people who don't touch a terminal

Claude Code (Module 12) brought agentic, multi-step AI capability to developers. Claude Cowork takes that same underlying idea and brings it to everyone else — knowledge workers who need real work done on their files and folders, without ever opening a command line. This module covers: 🎯 What Cowork actually is — and how it differs from Chat and from Code 📁 The folder-permission model — how it gets access, and what that means 🧩 Real use cases — the kind of work it's built to handle ⚠️ Honest risks — a real reported incident worth understanding 🛡️ Using it responsibly — practical habits that keep you in control This one connects directly to Module 5's agent concepts and Module 10's Desktop overview — worth having both fresh if you haven't covered them yet.

## Cowork in one sentence: an AI coworker, not a chat window

Claude Cowork is an autonomous agent mode within Claude Desktop that plans, executes, and completes multi-step tasks on your local files with minimal supervision — built on the same underlying architecture as Claude Code, but designed for people who don't write code. Analogy Chat answers questions. Cowork gets assigned work. Talking to Chat is like asking a knowledgeable colleague a question at their desk — they answer, you act on it. Working with Cowork is like handing a task to a capable assistant and walking away — they figure out the steps, do the work, and bring you the finished result. The shift in mental model matters: instead of writing a prompt and getting a response, you're describing an outcome and delegating the execution. This is the same "think → act → observe → decide" agent loop from Module 5, just applied to everyday knowledge work like spreadsheets and documents instead of code. 💡 Where it fits: Chat = conversation. Cowork = autonomous execution for general knowledge work. Code = autonomous execution specifically for software projects. Same underlying agentic capability, different audiences and file types.

## The folder-permission model

Cowork doesn't get free rein over your entire computer. It operates through a folder-permission model: you explicitly grant it read, write, and create access to specific directories, and it works within that boundary. 1 You choose the folder Point Cowork at a specific directory — not your whole file system — where the relevant files for the task actually live. 2 You describe the task In plain language — "organize these invoices into a spreadsheet," "summarize these meeting notes into one document." 3 It plans and executes autonomously Within that granted folder, it reads files, creates new ones, and organizes content — without needing you to approve each individual action along the way. 💡 Why the scoping matters: Granting access to one project folder rather than your entire Documents directory limits the blast radius if something goes wrong — the same principle as giving someone a key to one room rather than the whole building.

## The kind of work Cowork is actually built for

Concrete examples make this land better than the abstract description: 🧾 Turning invoices into a spreadsheet Point it at a folder of PDF invoices and ask for a formatted spreadsheet with the totals extracted — Cowork reads each file and builds the working output. 📝 Consolidating scattered notes into one document A folder of loose meeting notes becomes a single, organized summary document, without you manually piecing it together. 📊 Pulling metrics into a formatted report Gathering scattered figures into one coherent, presentable report — the kind of task that's simple in concept but tedious to assemble by hand. 🗂️ Organizing a messy folder by content Sorting files based on what's actually inside them, not just filenames — something that requires actually reading each file to do well. 💡 The common thread: Every one of these tasks involves real files, multiple steps, and a defined outcome — exactly the shape of work that benefits from delegation rather than a single conversational answer.

## A real incident worth knowing about

Being clear-eyed about risk makes a tool more useful, not less. One documented example is worth understanding directly: early user reports described a case where Cowork consumed a large volume of files (reported as around 11GB) during testing, unintentionally. ⚠️ Why this happened, most likely: Cowork operates with real read/write/create access within its granted folder and works autonomously — meaning a misunderstood instruction or an edge case in a task can result in real, unintended changes to real files, not just a wrong text answer you can simply disregard. This connects directly to Module 5's trust-boundary framework: reading files is low-risk and reversible. But writing, overwriting, or deleting files is a different category — those actions have real, sometimes hard-to-reverse consequences, which is exactly why backup practices matter here in a way they don't for a purely conversational tool. Low risk Reading and analyzing files Reversible by nature — nothing is altered. Medium-to-high risk Creating, modifying, or reorganizing files Real changes to real data. Worth having backups before granting broad access, especially for a new or unfamiliar task.

## Practical habits for staying in control

None of the risk above means avoiding Cowork — it means using it with the same reasonable caution you'd apply to any tool with real access to your files. A few concrete habits: 💾 Back up before granting access to anything important Especially for a new or unfamiliar type of task — a backup turns a potential disaster into a minor inconvenience. 🔍 Scope folder access narrowly Grant access to the specific project folder the task needs, not a broad parent directory "just in case." 🏢 In a workplace setting, governance is a real responsibility Anthropic itself has been clear that while some oversight tooling exists, organizations rolling out Cowork broadly are responsible for their own governance and controls — this isn't something to assume is fully handled for you. ✅ Review results before treating them as final Especially early on, or for anything consequential — the same "verify before you fully trust" habit from Module 7's discussion of AI reliability. 💡 The mindset that ties it together: Cowork's power comes from autonomous, real-world file access — which is exactly why the same care that applies to any powerful tool with real consequences applies here too.
