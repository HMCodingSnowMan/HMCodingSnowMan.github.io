## Claude Desktop: same Claude, a lot more reach

If you've only ever used Claude in a browser tab, you've been using one surface of a much bigger app. Claude Desktop is a downloadable application for macOS and Windows that gives Claude direct access to things the browser simply can't reach — your local files, your terminal, other apps on your screen. This module covers: 🗂️ The three modes — Chat, Cowork, and Code, and what each is actually for 🌐 Desktop vs. the browser — what genuinely changes when you switch 🔌 Local file and app access — why this is the core unlock 🧩 Real use cases — concrete tasks each mode handles well 🎯 When to actually switch — so you're not just downloading it for no reason None of this requires any technical background — Desktop is built for exactly the kind of everyday work you're probably already doing in the browser, just with fewer walls around it.

## Three modes, three different jobs

Claude Desktop organizes everything into three tabs. They share the same underlying Claude, but each is tuned for a different kind of work. 💬 Chat Familiar Works just like claude.ai in the browser — conversation, projects, memory, artifacts. No local file access. Good for questions, brainstorming, and generating text. 🤝 Cowork Autonomous An agent that runs multi-step tasks on your actual files — organizing folders, building a spreadsheet from a stack of invoices, drafting a document from scattered notes. You describe the outcome; Cowork handles the steps. 💻 Code Developer Agentic coding at the project level — reads your codebase, edits multiple files, runs commands, works with git. Built for people writing or maintaining software. 💡 Key distinction: Chat is for conversation. Cowork and Code are for actual execution — they take real action on your files rather than just describing what you could do.

## What actually changes when you leave the browser

It's tempting to think of Desktop as "the browser app, but in a window." That undersells it. Here's what's genuinely different: Browser (claude.ai) Desktop app Local file access None — you upload files manually Direct — Claude reads and writes files on your computer Multi-step autonomous tasks Limited Full Cowork support Coding at project level Not available Built-in Code mode Other app control Not available Available on supported systems, with per-action approval Quick access Requires opening a browser tab Global keyboard shortcut from anywhere Analogy Browser Claude is a visitor. Desktop Claude has a key to the building. A visitor can talk to you about the building, look at things you show them, and give advice — but they can't open a filing cabinet on their own. Desktop hands Claude a key: it can open the drawer itself, read what's inside, and put something new in, all with your approval at each step. 💡 Worth knowing: More reach means more responsibility on your end too — actions on your local system typically ask for approval, and it's worth paying attention to what you're approving, especially for anything that changes or deletes real files.

## What people actually use each mode for

Concrete examples make this click faster than abstract descriptions: 📁 Cowork: organizing a messy downloads folder "Sort this folder by file type and rename anything with a generic filename based on its content." Cowork opens each file, understands what it is, and reorganizes — something that would take you an hour manually. 📊 Cowork: turning scattered notes into a report Point it at a folder of meeting notes and ask for a single, formatted summary document — Cowork reads everything and produces one coherent output. 🐛 Code: fixing a bug across multiple files Describe a bug in plain language; Code traces it through the actual codebase, identifies the root cause, and proposes or makes the fix across however many files are involved. 💬 Chat: everyday questions and drafting No local file work needed — just the same conversational Claude you'd use in a browser, but with the convenience of a dedicated app and global quick-access shortcut. 💡 Pattern to notice: The more a task involves "go do this thing to my actual files/system" rather than "tell me about this," the more it's a Cowork or Code job rather than a Chat job.

## When it's actually worth switching to Desktop

Desktop isn't strictly better for everything — it's better for specific kinds of work. Here's a practical way to decide: ✅ Switch to Desktop when... You need Claude to work directly with files already on your computer, run a multi-step task without narrating every step yourself, work with code across a real project, or you find yourself constantly uploading the same kinds of files to the browser version. 🌐 The browser is still fine when... You're just having a conversation, need quick access from a device without the app installed, or you're doing lightweight work that doesn't touch your local file system at all. 💡 Bottom line: Desktop earns its place when the task is really about doing something to files, folders, or code that live on your machine — not just talking about them. If you've never once wished Claude could "just go check that file for me," you may not need it yet — but once you do wish that, Desktop is the answer.
