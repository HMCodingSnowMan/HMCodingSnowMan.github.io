## Claude isn't just a chatbot anymore. It can act.

Up to now, you've probably thought of Claude as something you talk to — you type a question, it types back an answer. That's true, but it's only half the picture. Claude can also use tools — search the web, run code, read files, browse websites, edit documents, and call other software — all in service of actually completing a task, not just describing how you might do it yourself. 🔧 What tool use actually is — Claude calling outside systems mid-conversation 🔁 The agent loop — how Claude decides what to do, does it, and checks its work 📊 The agentic spectrum — from simple tool calls to fully autonomous agents 🛡️ Trust and permissions — why some actions need your approval and others don't ⚙️ Where this shows up — real examples you've probably already used By the end you'll understand not just what "agentic AI" means, but why it's such a big shift from the chatbot era.

## Tool use: giving Claude hands, not just a voice

On its own, an AI model is really good at one thing: predicting the next chunk of text based on everything it's seen before. That's powerful for writing and reasoning, but it has a hard limit — it can't check today's weather, can't run your code, can't look inside a file you uploaded five minutes ago. Analogy Think of Claude as a very smart consultant in a sealed room Without tools, that consultant can only give advice based on what they already knew walking in. Tool use is like handing them a phone, a laptop, and a set of keys — now they can look things up, run the numbers, and go check something themselves instead of guessing. A "tool" in this context is just a defined action Claude can trigger — a function it can call, with specific inputs, that does something in the real world and returns a result. Web search is a tool. Running Python code is a tool. Reading a spreadsheet is a tool. 💡 The key shift: Instead of Claude guessing an answer from memory, it can go get the actual, current, verified answer — and show its work along the way.

## How Claude actually decides what to do

When Claude has tools available, it doesn't just blurt out an answer. It runs through a loop — think, act, observe, repeat — until the task is actually done. 1 Think Claude reads the request and decides what's actually needed to answer it well — does this need a tool, and if so, which one? 2 Act Claude calls the tool — say, a web search — with specific inputs, like a search query. 3 Observe The tool returns a result — search snippets, code output, file contents — and Claude reads it. 4 Decide Is that enough to answer well? If yes, respond. If not, loop back to step 1 — maybe a different search, or a second tool. ↻ This can repeat many times before you see a final answer This is very different from a single text prediction. It's closer to how a person actually solves an open-ended problem — try something, look at what happened, adjust, try again. 💡 Why this matters: When you see Claude searching multiple times, or running code and then fixing an error, that's the loop in action — not Claude struggling, but Claude iterating the way a careful person would.

## The toolbox: what Claude can actually reach for

Different tools unlock different capabilities. Here are some of the most common ones you'll run into: 🔍 Web search Finds current information beyond the training cutoff — news, prices, current events, recent releases. 💻 Code execution Actually runs code rather than just writing it — meaning math, data analysis, and file processing can be verified, not guessed at. 📄 File & document tools Reads uploaded files (PDFs, spreadsheets, images) and creates new ones — reports, slide decks, spreadsheets. 🌐 Browser control Navigates real websites, clicks buttons, fills forms — for tasks that require interacting with a live site, not just reading it. 🔌 Connected apps (MCP) Talks to external services — calendars, project trackers, databases — through a standardized connection protocol. 💡 Key idea: None of these are built into the model itself. They're external systems Claude is given permission to call. Swap the toolset, and the same underlying model can do very different jobs.

## "Agentic" isn't one thing — it's a spectrum

People throw around the word "agent" a lot, but it's not a single on/off switch. It's more like a dial, from a plain chatbot on one end to a fully autonomous system on the other. Least agentic Most agentic Plain chatbot: answers using only what it already knows, no tools at all Single tool call: uses one tool, once, to answer a specific question (e.g. one web search) Multi-step tool use: chains several tool calls together, adjusting based on results, to complete a task Autonomous agent: given a broad goal, plans its own steps, and works largely unsupervised toward completion Most of what you interact with day-to-day sits in the middle — multi-step tool use. Fully autonomous agents (the far right) are newer, more powerful, and require a lot more trust, since they're making more decisions with less human checking in along the way. 💡 Practical takeaway: When evaluating any "AI agent" product or claim, ask where on this spectrum it actually sits. A lot of "agentic" marketing describes something closer to a single tool call than genuine autonomy.

## Why some actions need your OK — and some don't

Not all tool actions carry the same risk. Reading a public webpage is very different from sending an email on your behalf or spending your money. Responsible agentic systems reflect that with different levels of oversight. Low risk — usually automatic Read-only, reversible actions Searching the web, reading a file, running a calculation. Nothing changes in the outside world, so these typically don't need explicit permission each time. Medium risk — often confirmed Actions with real but limited consequences Drafting an email (not sending), creating a file, modifying a document you're actively working on. Usually shown to you before anything is finalized. High risk — should always require approval Irreversible or high-stakes actions Sending a message on your behalf, making a purchase, deleting data, agreeing to terms. Good agentic systems are designed to pause and ask before crossing this line — not act first and explain later. ⚠️ Why this matters for you: As AI agents get more capable, understanding this permission boundary is genuinely useful — it's the difference between a tool that saves you time and one that takes unwanted action in the real world. Good systems make this boundary clear and give you control over it.

## Spot the risk level

Imagine an AI agent is helping you plan a birthday party. It searches for venue options, drafts an invitation, and is about to send that invitation to your guest list via email. In your own words, explain which of these three steps should require your explicit approval before happening, and why.
