## Claude Code: an agent that actually works inside your codebase

This module builds directly on Module 5 (AI Agents & Tool Use) — if that one isn't fresh, it's worth a quick review, since everything here assumes you understand the agent loop and trust boundaries already. Claude Code is an agentic coding tool: it reads your codebase, edits files, runs commands, and integrates with your development tools. It's aimed at developers, but also at technically-curious non-engineers who want to build or fix something real. 🖥️ Where it runs — terminal, IDE, desktop app, and browser 🔁 How a real task actually flows — from plain-language request to working code 🔧 Git and MCP integration — connecting to your existing workflow and tools 🛡️ Trust and approval in practice — applying what Module 5 covered, concretely 🎯 When to reach for it — vs. a quick chat-based coding question

## One tool, several surfaces

Claude Code isn't tied to one interface — it's designed to fit into wherever you already work: ⌨️ Terminal The original and most common surface — run claude from your project directory and start describing what you need in plain language. 🧩 IDE (VS Code, JetBrains) Works as an extension inside the editor you already use, so changes and context stay visible alongside your normal coding environment. 🖥️ Desktop app Lives in the Code tab of Claude Desktop (see Module 10), with the same underlying capability as the terminal version. 🌐 Browser / Web A web-accessible surface for cases where installing a local tool isn't practical or desired. 💡 Practical note: Most surfaces require a Claude subscription or an Anthropic Console account to use — it's worth confirming your specific plan supports the surface you want before diving in.

## From plain language to a working fix

Here's what a real Claude Code interaction typically looks like, tying directly back to the agent loop from Module 5: 1 Describe the goal in plain language "Add a dark mode toggle to the settings page" or paste an error message and describe the symptom. 2 Claude Code reads the relevant parts of your codebase It doesn't need you to specify every file — it explores the project to find what's relevant, the way a new team member would when investigating an issue. 3 It plans an approach, then writes the code Changes may span multiple files — this isn't a single-line autocomplete, it's coordinated editing across a real project. 4 It verifies the work Running tests or checking that the change behaves as expected, rather than just handing you unverified code and moving on. $ claude > Add a dark mode toggle to the settings page 💡 This is the agent loop from Module 5, made concrete: think (understand the request and codebase) → act (write and edit code) → observe (run tests, check results) → decide (done, or loop back and adjust).

## Working with git and your existing tools via MCP

Two integrations matter a lot for how Claude Code fits into a real workflow: Git integration It works directly with version control, not around it Claude Code can stage changes, write commit messages, create branches, and open pull requests — meaning it participates in your actual development process rather than producing code you then have to manually integrate yourself. $ claude "commit my changes with a descriptive message" The second integration is MCP (Model Context Protocol) — an open standard for connecting AI tools to external systems. This is the same underlying concept from Module 5's discussion of connected apps, applied specifically to development work. With MCP, Claude Code can read design docs in Google Drive, update tickets in a project tracker like Jira, pull data from Slack, or connect to custom internal tooling your team has built — extending what it can access well beyond just the code files in front of it. 💡 Why this matters: Real development work rarely lives in code alone — it touches tickets, docs, and team communication. MCP is what lets Claude Code participate in that fuller picture instead of being isolated to just the files on disk.

## Apply the trust framework

Recall Module 5's trust levels (low/medium/high risk actions). Using that same framework, classify these three Claude Code actions and explain your reasoning: (1) reading through your codebase to understand its structure, (2) writing a fix for a bug in a local branch, (3) opening a pull request that merges directly into your production branch.

## When to reach for Claude Code vs. a quick chat question

Not every coding question needs the full agentic tool. Here's a practical way to decide: Quick chat is enough Isolated questions and small snippets "What does this regex do?" or "write a function that reverses a string" — no need to touch your actual project files for this. Claude Code starts to make sense Fixing a bug that requires understanding how multiple files interact, adding a feature that touches several parts of a real codebase, or anything where "explore first, then act" is genuinely needed. Definitely Claude Code Full project-level work Refactoring across a codebase, working with git history and branches, or any task where the integration with your actual development tools and workflow matters. 💡 The deciding question: Does this task need Claude to actually see and act on your real project — reading real files, running real commands, working with real git history? If yes, that's Claude Code. If it's a self-contained question you could answer on a whiteboard, plain chat is simpler and faster.
